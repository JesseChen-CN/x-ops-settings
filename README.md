# x-ops-settings

Posting and auto-replies for @jessechen1991 (陈不忧) run here on GitHub Actions, so they don't depend on a Claude session.

- `.github/workflows/post.yml` is started every 5 minutes from 07:00 to 23:59 Beijing time by cron-job.org (GitHub's own schedule is a backup).
- `scripts/post_due.py` posts approved queue items that are due: at most 1 per run, and at least `min_gap_minutes` after the previous post.
- `scripts/send_replies.py` sends queued replies to comments under @jessechen1991's own posts (20-40 s apart, max 30 per run, stops at the first error).
- `.github/workflows/fast-reply.yml` runs right after every posting run: `scripts/fast_reply.py` finds new comments under @jessechen1991's own posts, has Claude write the replies (`scripts/reply_style.md`) and sends them (20-40 s apart, max 30 per run, never twice to one comment, no more replies under a post to someone who sends the same comment twice in a row under it). State and a log of sent replies are in `data/fast_reply/`. Switch: `fast_replies_enabled`.
- User profiles (Jesse 2026-10-23): after each fast-reply run, every `people_every_hours` (8), `scripts/people.py` has Claude write profiles of the people who comment most (top `people_top` of today and yesterday, plus anyone with a profile who came back) and notes on what is going on in the Chinese X circle. No extra X API reads: it uses the comments `fast_reply.py` already fetched (`data/people/comments/`) and the replies it sent. `fast_reply.py` passes each commenter's profile, our last exchanges and the recent circle events to Claude. Files: `data/people/profiles.json`, `data/people/画像.md` (readable), `data/people/circle.jsonl`, `data/people/overrides.json` (Jesse's corrections, win over Claude). The reply radar in the project reads them via `repo_sync.py people` and adds circle events via `repo_sync.py circle`.
- `.github/workflows/follow.yml` also runs after every posting run: `scripts/auto_follow.py` follows at most 1 verified candidate per run from `data/follow/candidates/` (pushed by the project's `repo_sync.py` from the daily follow check), about 85-110 a day (each day picks its own number), paced evenly between 09:00 and 22:00 Beijing, never the same account twice, never unfollows. Any API error writes `data/follow/stopped.json` and stops all following until that file is deleted. Log: `data/follow/log/`. Switch: `follow_enabled`.
- `data/queue/` and `data/replies/` are written by the project's `repo_sync.py`. `data/results/` and `data/reply_results/` are written only by Actions.
- `data/config.json` has the on/off switches `posting_enabled` and `replies_enabled`.

The X API keys live in this repo's Actions secrets: `X_API_KEY`, `X_API_SECRET`, `X_ACCESS_TOKEN`, `X_ACCESS_TOKEN_SECRET`. Claude for fast replies uses `CLAUDE_CODE_OAUTH_TOKEN` (from `claude setup-token`, runs on the Claude subscription) or `ANTHROPIC_API_KEY`. Never put keys or tokens in repo files: this repo is public.
